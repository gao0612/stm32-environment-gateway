# 1.1版本：代码行为与取舍

## Flash写入

在线、无历史积压时，从16条RAM环形队列取样本直接发送，PUBACK到达后弹出，不写入采样缓存。日志仍写入Flash。

离线时，RAM有4条或最早待处理条目等待约2秒便尝试转存，每批最多4条，每次成功落盘才弹出。已有磁盘积压且RAM达到4条时也转存，优先发送旧磁盘记录。存储满或写失败保留RAM前端并增加错误数，最终RAM/采集转发队列满时会出现明确丢弃计数。

这是一种减少在线写入的策略，不是把多条压缩为一次页编程。离线时每条仍有CRC、读回校验和最后提交。实际延时受调度、网络等待和Flash耗时影响，2秒是触发阈值，不是严格的数据安全窗口。

在线待确认消息、RAM批次和消息队列都可能在突然断电时丢失。如业务要求每次采样均可跨掉电保留，应使用1.0版“先持久化再发送”策略并评估写入寿命。

JSON新增sample字段，缓存记录text区域保存采集sequence，不改变64字节记录大小。新消息建议按device+boot+tick+sample去重，number在RAM和Flash路径中的含义不同，不再单独作为统一业务编号。旧版缓存的sample可能为0，应兼容旧版device+boot+number规则。

## 网络恢复

连续失败使用1/2/4/8/16/32/60秒重试等待，60秒封顶；稳定在线30秒才重置，避免短暂上线后不断从1秒重试。网线未连接时不不断发起TCP连接。TCP和MQTT应答仍有独立超时，PUBACK不匹配不会删除消息。

诊断原因：CHIP/SPI、CABLE、TCP、AUTH、PROTOCOL、PUBACK、PING、STORAGE。状态和计数通过临界区复制给显示任务，不让LVGL直接读一组正在变化的字段。

## 显示与日志

短按顺序：温湿度、设备、日志、诊断。普通页面长按进入日志并向旧记录移动；诊断页长按循环选择WARN/ERROR/INFO日志筛选并跳转日志页。只在最近64个物理记录中查找匹配日志。

INFO=1、WARN=2、ERROR=3，日志分区记录type表示等级；采样分区type仍表示设备状态。旧版日志type=1兼容INFO。诊断页显示链路、MQTT、Flash识别、RAM/DISK、上传/实时上传、丢弃/存储错、最小RTOS堆和复位标志。

本机测试覆盖存储/报文/策略；没有在电脑模拟完整Broker、RTOS调度或GPIO时序，待按验收表上板检查。
