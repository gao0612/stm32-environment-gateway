# 代码导读

## 从哪开始

1. `Core/Src/main.c`：读取复位原因、HAL初始化、系统时钟、各外设初始化、`Gateway_Init()`、初始化内核、创建任务、启动内核。
2. `App/Tasks/gateway.c`：读取参数并初始化显示；创建业务队列和任务，启动看门狗。
3. `App/Tasks/sensor_task.c`：每秒发一次Modbus查询，等待收数，解析并发布快照。错误中断只记状态和通知，任务负责重启接收。
4. `App/Tasks/gateway_task.c`：消费采集快照，检查新鲜度，分别转发给显示和网络队列。
5. `App/Tasks/network_task.c`：初始化外部Flash，扫描已有记录；管理W5500和MQTT；在线先从RAM发送，离线转存Flash；收到PUBACK后释放RAM或标记Flash已发送。
6. `App/Tasks/screen_task.c` 与 `App/UI/screen_ui.c`：只有显示任务调用LVGL。按键任务只发切页指令。
7. `App/Tasks/task_health.c`：检查四个关键任务的心跳；超时后锁定故障并停止喂狗。

## 数据怎样走

```text
UART DMA/IDLE -> 环形缓冲 -> 采集任务解析 -> 快照队列 -> 转发任务
                                                        |-> 显示队列 -> LVGL -> ST7789
                                                        |-> 网络队列 -> W25Q64 -> MQTT
                                                                            PUBACK -> 已发送标记
```

## 文件和函数命名

文件按作用命名：`sensor_task`是采集任务，`mqtt_packet`组装报文，`flash_store`管理记录。已有 `AppParams_Load` 一类接口保留清晰的模块前缀，静态辅助函数只在本文件可用，没有引入复杂对象框架或多层回调注册。

|常用接口|作用|
|---|---|
|`Network_Publish()`|将一份采集结果放入网络队列|
|`Network_Log()`|复制一条短事件到日志队列，不阻塞采集|
|`Store_SaveSample()`|在外部Flash追加一条数据|
|`Store_Peek()`|读取最旧的未确认数据|
|`Store_Ack()`|只标记对应编号的数据已上传|
|`Store_LogRead()`|从新到旧读取最近64条日志|
|`Flash_Read/Write/Erase()`|W25Q64底层访问，存储模块统一加锁|
|`Mqtt_Connect/Publish/Subscribe()`|生成MQTT二进制报文，不负责网络收发|

## 为什么还有这些检查

简单代码仍需保留长度检查、CRC、超时、Flash提交标志和DMA缓冲区生命周期。它们直接影响错误时的行为，不能为了缩短函数而去掉。

外部记录为64字节：magic、编号、boot、tick、温湿度、状态、短文本、CRC、commit、sent。CRC覆盖前52字节，先写内容和CRC，读回比较，再写commit。sent不参与CRC，收到MQTT确认后只将其从全1改为指定标记。

内部参数A/B区与外部日志/缓存完全分开：片内扇区10/11各128KB存参数，W25Q64前4MB日志、后4MB待发送数据。任何地方都没有“整片Flash清空”的启动操作。

## 任务和资源

采集任务 AboveNormal；转发/按键/健康任务 Normal；显示/网络 BelowNormal。网络与显示都使用阻塞等待或短延时主动让出CPU。掉线不会停止网络任务心跳；只有任务执行停滞才会触发系统级复位。

32KB FreeRTOS堆用于任务栈、队列和互斥量；32KB LVGL内存池独立。显示6144字节栈，网络4096字节栈，其他任务通常1024字节。实际余量应在上板长时间运行时观察。

目前日志内容为英文短事件，适应现有西文字体。后续加入中文界面时再添加经过裁剪的中文字库，避免把字体占满Flash。
