# 配置、运行和Git提交

## 编译下载

使用CMake/Ninja与arm-none-eabi-gcc，在根目录运行README中的两条命令。使用VS Code + STM32扩展打开整个目录，不要只打开某个源文件。`launch.json`保留STM32F407ZGT6、SWD和1000kHz配置；ST-Link失败时先查供电、接线、占用和速度。

不自动下载到板上，不自动擦除已保存的参数。完整固件从0x08000000开始，程序链接范围768KB，末尾两个128KB片内参数扇区保留。

## 网络配置

1. 复制 `App/Config/secrets.example.h` 为 `secrets.h`，填实际MQTT服务器IPv4、端口、客户端ID和账号。
2. 查看 `App/Storage/app_params.c` 中静态IP、掩码、网关。若片内已有合法A/B参数，会优先加载，改默认表不会覆盖旧参数。
3. 需要改已存参数时，先在 `Gateway_Init()` 创建局部 `AppParams_t`，调用 `AppParamsStore_Save()` 保存经过校验的候选值，再重新加载。该操作仅用于启动阶段，禁止在活动采集任务里频繁擦写片内Flash。
4. 电脑直连可先使用同网段静态IP，在电脑运行MQTT Broker并允许对应端口；云端服务器需有可达的网关。配置默认服务器只是示例，不保证它存在。
5. Broker需支持MQTT3.1.1、QoS1、订阅和无TLS TCP。若云平台只允许TLS，本版本需要后续增加TLS终端或网关，不要直接改端口冒充TLS。

发布主题 `gateway/sensor`，命令主题 `gateway/cmd`。向命令主题发送文本 `next` 可切页和亮屏。收到其他命令只记录事件，不执行任意系统操作。

JSON示例：`{"device":"f407-gateway-01","boot":3,"number":18,"tick":13000,"temperature_x10":275,"humidity_x10":620,"state":1}`。state具体枚举见 `device_health.h`；数值是最近保存样本，离线/过期时应结合state使用。

## 屏幕

- 短按：温湿度 -> 设备状态 -> 日志/网络 -> 温湿度。
- 长按超过800ms：切入日志页，向前查看一条旧日志；最近64条可浏览，继续长按循环。
- 30秒无按键关闭背光；后台刷新、采集、上传仍运行。短按或 `next` 唤醒并执行切页。
- MQTT OK表示CONNACK与SUBACK已通过；MQTT OFF不等于MCU或W5500损坏。

## 关键限制

先落盘再发送便于理解，在线时也写Flash，存在写入磨损和上电扫描时间。缓存满不覆盖旧消息，错误计数可在 `network_monitor.store_errors` 观察。`queue_drops`、`log_drops` 表示RAM队列满。此版本没有零丢失或无限缓存承诺。

## Git/GitHub

目录内已准备 `.gitignore`、应用MIT许可证和第三方说明；未创建远程仓库、未推送。确认 `secrets.h` 不被跟踪、填完本版本测试记录后再运行：

```powershell
git init -b main
git add .
git status --short
git commit -m "Add STM32F407 gateway learning project"
# 在GitHub新建空仓库，将下行改成自己的仓库地址
git remote add origin https://github.com/YOUR_NAME/stm32-gateway.git
git push -u origin main
```

不要提交build、调试日志、账号密钥或他人的个人信息。Git身份使用你自己的账户配置。保留来源说明，简历可描述为“参考开源项目完成硬件适配、功能复现与整理”，并具体说明你掌握的实现与测试。
